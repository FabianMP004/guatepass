# Tarea 10: portal mínimo y tiempo real

La página estática carga config.json derivado de Outputs. Cognito autentica con USER_PASSWORD_AUTH del app client sin secreto y entrega ID token al API Gateway y AppSync. Los tokens viven solo en sessionStorage para sobrevivir a recargas de página dentro de la misma pestaña; la actualización usa REFRESH_TOKEN_AUTH y el cierre de sesión borra la sesión local. El rol sale exclusivamente de claims del ID token, y cada Lambda valida propiedad/rol de nuevo. Navegación conductor: saldo, recarga, tags, pagos y facturas; operador: día/peaje propio y eventos en vivo. Estados pendientes se muestran con vencimiento desde GET /passes para operador y el conductor consulta los pasos propios mediante el nuevo GET /users/{placa}/passes.

Historial de movimientos y facturas lee GSI por placa y pagina con cursor restringido a esa placa; ninguna decisión financiera se toma en GSI. Para tiempo real, EventBridge entrega eventos al SQS y Lambda publica con SigV4 IAM en AppSync Events /peajes/p-{peaje_id escapado}: guion → -0, guion bajo → -1; la misma conversión se aplica al token y al publicador; navegador solo se suscribe con Cognito. El servidor restringe la suscripción a grupo operador y peaje exacto del token. El operador conecta primero, amortigua mensajes mientras consulta GET /passes y luego aplica versiones mayores por paso_id. Al reconectar vuelve a consultar. Un paso COBRADO no retrocede a PENDIENTE.

Se reutilizan el API, AppSync, S3 privado, CloudFront y outbox existentes; no se crean segundos recursos públicos. La entrega CP2 requiere pruebas manuales de Juan/Andrés con usuarios reales de demo y webhook con clave backend. No inventar una credencial de cámara ni incluirla en config.json.
